## STEP 3 — 리팩토링 내용

| Layer | 변경 | 의도 |
|------|------|------|
| boundary/input | `try_parse_and_validate` 추가, `validate_raw`가 `parse_input` 재사용 | validation 흐름 단일화, 파싱 중복 제거 |
| control/flow | `validate_raw` + `parse_input` 이중 호출 제거 | control 책임을 orchestration에 집중 |
| entity/registry | `BASE_UNIT`, `DEFAULT_UNITS` 기반 기본 registry 구성 | constants SSOT와 registry 초기값 정합성 강화 |
| boundary/output | `_format_table`, `_format_json`, `_format_csv` 분리 | 포맷별 책임 분리, 확장 시 변경 범위 축소 |

---

## STEP 4 — 유지한 계약

다음 공개 API와 테스트 계약은 변경하지 않았습니다.

- `boundary.input.validate_raw(raw, known_units) -> str | None`
- `boundary.output.format_results(..., fmt="table") -> str`
- `control.flow.run_conversion(raw_input, output_format="table") -> str`
- `entity.converter.convert_all(source_unit, value) -> dict[str, float]`
- ECB 의존 방향: `boundary → control → entity`
- Error code 책임: E001~E005는 boundary only
