## STEP 1 — Mom Test 요약

### 페르소나

**meter / feet / yard** 를 쓰는 **학습자** — `단위:값` 한 줄로 같은 길이를 여러 단위로 보고 싶다.

### Mom Test 증거 (과거·구체)

1. `meter:2.5` 입력 시 **feet·yard 등을 바로** 보고 싶다.
2. `3.28084`, `1.09361` 비율을 **매번 손으로 계산**하기 번거롭다.
3. cubit 같은 **새 단위**를 쓰려면 **코드 if/elif 를 고쳐야** 한다.

### 표면 문제 (잘못된 정의)

「Python **단위 변환기 프로그램**을 만든다」

→ TDD·JSON·Cursor가 문제 정의에 섞인 문장. **하지 않을 것**과 구분한다.

### 진짜 문제 (한 문장)

**여러 길이 단위로 같은 값을 맞출 때 환산 비율 계산·코드 분기 증식으로 오류와 수정 비용이 커진다.**

## STEP 2 — 도메인 고정

| 항목 | 값 |
|------|-----|
| 기준 단위 | **meter** |
| 고정 비율 | 1 m = **3.28084** ft · 1 m = **1.09361** yd |
| 파생 규칙 | ft ↔ yd 는 **meter 경유** |
| 입력 형식 | `unit:value` (콜론 1개) |
| 초기 지원 단위 | meter, feet, yard |
| 출력 (1차) | 입력 단위 기준 **모든 등록 단위** 줄 출력 |

### README 예시 수치 (검증 기준)

입력: `meter:2.5`

| 대상 | 계산값 | README 표기(반올림 1자리) |
|------|--------|---------------------------|
| meter | 2.5 | 2.5 |
| feet | 8.2021 | 8.2 |
| yard | 2.734025 | 2.7 |

테스트: 내부 연산은 `FLOAT_TOLERANCE`, 표 출력은 **1자리 반올림** (U-OUT-01).

## STEP 3 — 세션 주제 (Mom Test 기반)

**길이 단위 환산을 손 계산·하드코딩 분기에 의존하지 않고, meter 기준 SSOT·등록형 변환기·입력 검증을 pytest RED/GREEN/REFACTOR 로 증명한다.**

### R-G-I-O

| | |
|---|---|
| **Role** | meter/feet/yard 변환이 필요한 **학습자** |
| **Goal** | 한 입력으로 **전 단위 결과**를 **정확히** 얻고, 잘못된 입력은 **에러 코드**로 거부 |
| **Input** | `unit:value` 문자열 (예: `meter:2.5`) |
| **Output** | 표/JSON/CSV (단계별) · 실패 시 E001~E005 |

### 성공 기준 (Mom Test 연결)

| ID | 기준 | 연결 |
|----|------|------|
| SC-1 | `meter:2.5` → feet·yard **수식 일치** | 증거 ① |
| SC-2 | 형식·숫자·단위·음수 **5종 거부** | README 품질 |
| SC-3 | cubit **등록만**으로 변환 | 증거 ③ · OCP |
| SC-4 | 비율 **설정 파일** 로드 | 추가 요구 |
| SC-5 | RED FAIL → GREEN PASS **로그** | MagicSquare 워크플로 |

## STEP 5 — 문제 정의 (PRD 연결)

### 핵심 질문

> **"주어진 `unit:value` 를 meter 기준으로 환산한 뒤, 등록된 모든 길이 단위 표현을 정확히 반환할 수 있는가? 입력·확장·출력 계약을 테스트로 추적할 수 있는가?"**

### 판정 규칙 (요약)

1. `unit` 은 registry에 등록됨
2. `value` 는 0 이상의 실수
3. 환산은 `meters_per_unit` SSOT 사용
4. 실패는 boundary 에서 E00x 반환 (entity 처리 금지)
